# 章节精简作业书（给执行者）

> 本文件是"把一章压到可读长度"的完整作业流程。**先读完这一份，再动手。**
> 规范细节见 `docs/WRITING-SPEC.md` 第二节、第六节；已完成 26 章的实测数据见 `docs/REFACTOR-v12-精简.md`。

## 零、你要达成什么

把一章的**正文散文**压短、去掉 AI 味，同时**不让读者读不懂**。四个门槛全部要过：

```
python scripts/lint_prose.py    NN-*.md      # 十项风格指标
python scripts/check_chapters.py NN-*.md     # 章首/章末/标题/表格/代码块结构
python scripts/trim_verify.py   NN --base 627ddd9 [--restructure]   # 代码输出表格逐字一致、引用不减
python scripts/check_reader.py  NN           # 四类锚点缺失（代码来源/输出出处/并列项总起/术语定义）
```

或一条命令：`python scripts/trim_all.py NN`（四列全绿才算过）。

## 一、流程（每章照做）

1. `python scripts/trim_split.py "NN-*.md"` —— 生成 `.trim/NN.seg.json` 与 `.trim/NN.view.md`；视图里 `⟦Pnnnn⟧` 是受保护块，其余是散文。
2. 打印散文段清单（**关键一步**）：
   ```python
   import json, re
   segs = json.load(open(".trim/NN.seg.json", encoding="utf-8"))
   runs, cur = [], []
   for s in segs:
       if s["kind"] == "S": cur.append(s["text"])
       else:
           if cur: runs.append(cur); cur = []
   if cur: runs.append(cur)
   zh = lambda s: len(re.findall(r"[\u4e00-\u9fff]", s))
   print("runs", len(runs))
   for i, r in enumerate(runs):
       print(f"{i:02d} [{sum(zh(x) for x in r):3d}] n={len(r)} {r[0][:24]}")
   ```
   `n=` 是该散文段里含几个自然段。**相邻的两个自然段属于同一个散文段**，改写时不能把一个自然段拆成独立一段。
3. 读 `.trim/NN.view.md`，写 `.trim/NN.new.md`：**只写散文**，段间用单独一行 `⟦GAP⟧` 分隔，段数必须等于 runs 数。段内可以合并自然段，**绝不能跨越受保护块合并**（会把解释文字挪到代码块前面）。
4. `python scripts/trim_apply.py NN .trim/NN.new.md` —— 段数不符会直接报错，修到过。
5. 跑四个门槛，改到全绿。
6. `Copy-Item .trim/NN.final.md "NN-*.md" -Force` 写回正式文件。
7. **不要执行任何 git 命令**；**不要跑 `gen_book.py build`、`check_nav.py`**（会改写全库文件，与并行的其他人冲突）——由主代理最后统一跑。

## 二、删什么（R1–R12）

| 规则 | 触发 | 动作 |
|---|---|---|
| R1 删元话语 | "这句话决定了…""值得注意的是""本节/下面/前面""先说清" | 整句删 |
| R2 情绪词换事实 | 致命、灾难、很贵、坑、烧钱、可怕 | 换成可测后果 |
| R3 去拟人 | 兜住、接住、扛住、看见、记住 | 换回代码对象 |
| R4 破折号补语合并 | `——` 后是同位语 | 合并或拆句（每章 ≤8 处） |
| R5 段落合并 | 连续 2 段各只有 1–2 句 | 并成 90–150 字 |
| R6 "不是 A 而是 B" 降频 | 每章 >2 处 | 留最有力一处 |
| R7 粗体只标值 | 粗体是判断句 | 去粗体，只留字段名/数字/命令（≤3.5%） |
| R8 删重复结论 | 同一判断在章首/节末/章末各一次 | 留信息量最大的一处 |
| R9 删第二人称 | "你""想象你是" | 改无人称（**必须为 0**） |
| R10 一句一事 | 一句三个以上分句 | 拆句 |
| R11 括号补充 | `（…）` ≥6 字 | 并入正文（≤10 处） |
| R12 压解释保因果 | 一节里"为什么"讲两遍 | 保留"缺什么→成因→怎么补→会怎么坏" |

## 三、四类锚点**禁删**（R13–R15，这是上一轮返工的根因）

| 类 | 禁删的句子 | 机器判据 |
|---|---|---|
| A1 | 代码块的来源句（"运行 `code/knowledge/chNN_xxx/foo.py`："或"下面是示意代码："） | 本节内须有 `code/knowledge/` 或 `.py` 或"示意/演示" |
| A1b | 输出块的出处（"运行 `…/foo.py` 的输出："或"它的输出："） | 输出块须能追溯到文件或紧邻上方代码块 |
| A2 | 并列项的总起句（"由此有三条推论：""两种做法各有代价："） | "第一，…"开头时前段须以"："或"三条/两种"收尾 |
| A3 | 术语/类名的首次定义句 | API/类名首次出现须有定义句或代码里出现 |
| A4 | 被后文指代的对象（"同一份 `Order` 定义"里的 Order） | 全章须有 `class Order` 或足够出现次数 |

**R14：代码块前后各一段视为受保护。** 代码块前那句"这段代码在讲什么"、后面 1–2 段的解释，只能按 R13 换掉，不许删空。
**R15：合并段落时禁止接重。** 同一句不许在一段里出现两次。

## 四、不许动的东西

代码块、输出块、表格、H1/H2/H3 标题行、章首引用块、`## 这一章建立的 N 件事`、`## 下一章`。

- 需要合并小节时**只改标题行**（Python 按行替换，**只在围栏代码块外替换**），**不许顺手合并连续空行**——那会压掉 Python 代码块里的 PEP8 双空行，`trim_verify` 的 fence 哈希立刻不一致。
- 表格不许移动顺序（`trim_verify` 按顺序比对）。
- 删句子带走 `第 N 章` / `x.y 节` / `code/knowledge/...` 引用时，**必须在别处补回等义引用**，否则 `trim_verify` 报"第N章 减少 / code路径 减少"。补引用会加字数，需同步删等量文字。

## 五、目标数值

| 指标 | 目标 |
|---|---|
| 散文汉字 | 4800–6250（原 7500–9300，压 25–35%） |
| 平均段长 | 80–140 字（纯删字会掉到 55–78，需补一轮"段内合并到 90–150 字"） |
| 粗体占比 | ≤3.5% |
| 破折号 / "不是…而是" / 括号补充 | ≤8 / ≤2 / ≤10 |
| 第二人称"你"、情绪词、拟人动词 | 0 |

散文顶到 6250 后就别再往这章加东西；要加必须先删等量。

## 六、结构（H2 过多时）

`WRITING-SPEC` 6.4：H2 目标 ≤6、H3 ≤15。超过时按"同一问句下的并列节"合并；**API 逐项对照的章（LangChain/LangGraph）允许 H2 到 11**。

合并后 `trim_verify` 必须加 `--restructure`，并且**不要**自己跑 `gen_book.py build`（目录由主代理统一重建）。

## 七、交付报告格式

每章一行：

```
第 NN 章：章汉字 X→Y（−Z%），散文 A→B，平均段长 M，lint ✓ chapters ✓ verify ✓ reader ✓；
        结构 H2 a→b / H3 c→d；标为"示意"的块 n 处（章节号）；补回引用 m 处
```

有问题（压不到区间、某类检查清不掉、发现原稿硬伤）单独列在报告末尾，**不要硬删知识点凑数**。

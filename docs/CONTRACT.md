## 填写规则

第 5 章完成后，必须在本文件补充以下内容。格式固定，便于下一个会话直接对照。

### 数据类型

```
类型名
  字段名: 类型  # 用途
```

示例（第 5 章完成后填真实内容）：

```
Step
  index: int        # 步号，从 0 开始
  plan_id: str      # 所属计划 id，无计划时为 ""
  instruction: str  # 这一步要做什么
  tool_name: str | None
  args: dict
```

### 接口签名

```
接口名
  方法签名  # 语义
```

示例：

```
Actor
  step(step: Step, state: State) -> ActionResult  # 执行一步，不判断对错
```

### 循环入口

```
run(...) -> ...
  返回字段说明
```

### 已知限制

记录本章刻意没做的事，避免后续章节重复实现或误以为已存在。示例：

- 第 5 章没有超时与重试，`Actor` 直接调用 `Tool.invoke()`，第 6 章在该调用点插入 `Resilience`
- 第 5 章没有重复检测，`reason` 的 `no_progress` 只按"连续两次相同 Step"粗判，第 7 章替换为指纹

---

## 为什么要这个文件

`OUTLINE.md` 5.7 只能写"计划"，写不了"实际"。如果第 5 章的实现与计划不一致（命名、字段类型、参数顺序），而第 6 章只读 `OUTLINE.md`，两边就会对不上。

本文件的作用是把"实际做了什么"固定下来，让下一个会话不必读代码也能确认契约。

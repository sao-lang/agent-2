# docs/ — 书的结构与规范

这里只放"书本身的结构与写作规范"，不放代码、不放示例。脚本在 [`../scripts/`](../scripts/README.md)，示例在 [`../code/`](../code/)，示例之外的推导分册在 [`../outline/`](../outline/)。

## 一、先记住一条：四个文件不能随便搬

有三条硬依赖，搬家或改名会直接打断流水线：

| 文件 | 谁依赖它 | 坏掉的样子 |
|---|---|---|
| `book.json` | `scripts/gen_book.py`、`check_nav.py`、`check_chapters.py` | 生成与校验全部失效；它是唯一事实源 |
| `INDEX.md` | 全部 60 章的章首链接 `./docs/INDEX.md#volN` | 每章顶部导航断链 |
| `WRITING-SPEC.md` | `gen_book.py` / `check_chapters.py` / `check_nav.py` 的口径说明都指向它 | 规范与机检脱节 |
| `OUTLINE.md` | `outline/` 全部 36 个分册的页首指针 | 加载规则失联 |

`INDEX.md` 是**生成物**，不要手改：改 `book.json` → 跑 `python scripts/gen_book.py build`。

## 二、分类与用途

| 目录 / 文件 | 回答什么问题 | 什么时候读 | 谁在改 |
|---|---|---|---|
| `OUTLINE.md` | 我要写/读某章，该加载哪几本分册？ | 每次写作任务开始 | 结构变更时 |
| `book.json` | 全书到底有几卷几章、每章标题与知识点是什么？ | 改结构、加章、查编号 | 结构变更时 |
| `INDEX.md` | 全书目录长什么样？（生成物） | 只读 | 不手改 |
| `WRITING-SPEC.md` | 一章该怎么写：章首六行、篇幅、标题、表格、机检阈值 | 动笔前、改规范前 | 规范变更时 |
| `plan/` | 这一卷为什么这么排章、为什么是这个顺序？ | 想改章节划分时 | 规划阶段 |
| `refactor/` | 前几轮是怎么施工的、当时为什么这么切？ | 追溯某个结构决定的来历 | 施工阶段 |
| `trim/` | 章节超长时怎么瘦身、动哪些不能动？ | 需要精简篇幅时 | 精简阶段 |
| `audit/` | 哪些知识点覆盖不足、哪些代码有缺口？ | 完工前的体检 | 审计阶段 |
| `harness/` | 卷 12 组件基座长什么样、契约怎么定？ | 写 48–53 章或做封装时 | 副线开发 |

## 三、`plan/` 里的文件

| 文件 | 内容 |
|---|---|
| `PLAN-v7.md` … `PLAN-v10.md` | 第 7–10 卷的章节方案（每轮一版，保留演进而非覆盖） |
| `PLAN-v11.md` | 当前基座：53 章的章节方案，章号沿用至此 |
| `PLAN-ARCH.md` | 编排架构相关章节（22/23/33/34/35/38/53）的节级计划 |

## 四、`refactor/` 与 `trim/` 的区别

- **refactor/** 改的是**结构与内容**：合并、拆分、重排、补缺口。读它是为了知道"这个结构为什么长这样"。
- **trim/** 改的是**篇幅**：把超长章节压回区间，同时保住代码输出、表格与引用的逐字一致。读它是为了知道"压字数时哪些东西不可触碰"。

## 五、命名约定

- `PLAN-vN.md`：第 N 版章节方案，**版本号只增不改**，旧版保留（它们是决定的证据）。
- `REFACTOR-vN-主题.md`：第 N 轮施工记录，主题用两字概括（`精简`、`结构`）。
- `AUDIT-对象.md`：审计报告，对象是 `CODE-GAPS` 或 `CONCEPTS`。

## 六、新增一个文档放哪

| 你要写的东西 | 放哪 |
|---|---|
| 章节怎么写、机检阈值 | 直接改 `WRITING-SPEC.md`（不新建文件） |
| 某一卷的章节划分方案 | `plan/PLAN-vN.md`（新版本号） |
| 某一轮的施工说明 | `refactor/REFACTOR-vN-主题.md` |
| 一次体检结论 | `audit/AUDIT-对象.md` |
| 组件契约与开发会话 | `harness/` |

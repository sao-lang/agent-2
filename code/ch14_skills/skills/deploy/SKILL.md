# 部署

## 什么时候用

用户说「发布到 staging」「上线」「rollout 30%」时。

**不要用于**：本地跑起来看看（那是 dev server）、改配置。

## 步骤

1. **确认环境**：dev / staging / prod。没说明就停下来问，不要猜
2. **确认分支已合并**：当前分支必须已经 merge 到主干，否则拒绝
3. **跑测试**：`run_test` 失败立即停止，不要「先发上去再说」
4. **灰度 1 个实例**：观察 5 分钟，看错误率与 P95
5. **逐步扩量**：1 → 10% → 50% → 100%，每步都看指标
6. **失败时保留旧版本**：回滚不是删除，旧版本必须还在

## 停止条件（任何一个触发就停）

- 错误率超过基线 2 倍
- P95 超过基线 1.5 倍
- 任何 5xx 突增

## 常见错误

- ❌ 一次全量发，出问题来不及回滚
- ❌ 测试失败但「手动确认没问题」继续发
- ❌ 回滚时把旧版本清掉了，没法退

# 退货审查

## 适用范围

- 适用：本平台自营商品的**退货**判定，含无理由退货、质量问题退货、生鲜与定制特例。
- 不适用：换货、维修、发票重开、物流投诉、价保。遇到这五类直接说明不属于本流程，不要硬套。
- 只回答"某一笔订单能不能退"。政策条文本身怎么规定，走检索，不激活本流程。

## 前置条件

1. 有订单号，且形如 `A1001`。
2. 能调到 `order__get_order` 拿到 `signed_days_ago` 与 `category`。
3. 能调到 `order__get_policy` 拿到 `window_days` 与 `clause`。

缺任一条就停下，问缺的那一项，不要用"通常 7 天"之类的默认值代替。

## 步骤

1. 取订单：调 `order__get_order`，读 `order_id`、`status`、`signed_days_ago`、`category`。
2. 判断能否进入流程：`status` 不是"已签收"时没有签收天数，回"待定"并说明原因。
3. 取窗口：调 `order__get_policy(category)`，读 `window_days` 与 `clause`。
4. 分流特例：`category` 是"生鲜"或"定制"时，先读 `references/exception.md` 对应段；用户提到"质量问题"时读 `references/windows.md` 的质量窗口行。
5. 判定并自检：跑 `scripts/decide.py`，把结论、天数、窗口、条款交给它核对；不一致以脚本为准，回到第 3 步查输入。
6. 组织回复：套 `templates/reply.md`，结论在前、依据在后、下一步一句。

## 判定规则

- 签收天数按自然日算，签收当天记为第 0 天。
- 窗口以工具返回的 `window_days` 为准，不在正文里写死 7 天。
- 两者相等算可退（第 7 天当天仍可退）。
- 无理由退货要求商品未拆封或不影响二次销售；用户明说已拆封且影响销售时判不可退。
- 质量问题不受 7 日限制，走 15 日窗口，且需要照片或检测报告。
- 生鲜只在 24 小时内、且变质或缺斤少两时可退；定制商品不支持无理由退货。
- 免运费门槛、优惠券、分期手续费不影响"能不能退"，只影响退多少钱；问金额时转财务。

## 资料（按需读，不要一次全读）

- `references/policy.md`：五章完整条款。用户质疑条款依据、或要求原文时读。
- `references/exception.md`：定制、预售、生鲜、大件的例外。类别命中时读。
- `references/windows.md`：四类窗口与质量窗口的速查表。需要跨类别比较时读。

## 脚本与测试

- `scripts/decide.py`：判定引擎。输入一条记录，输出结论与理由码；退出码 0 表示判定成立，1 表示输入不全。
- `scripts/check.py`：一致性校验。只检查"结论与两个数字是否自洽"，不重新判定。
- `tests/test_decide.py`：判定引擎的离线单测，改脚本后先跑它。

## 输出格式

```
结论：可退 / 不可退 / 待定
依据：
- 签收后第 N 天申请，窗口 M 天
- 适用条款：P-7
下一步：<一句可执行的话，或转人工的原因>
```

## 失败处理

- 工具报错：把错误原文转述给用户，不要换一种说法重试。
- 两个数字拿不到：输出"待定"并写清缺哪一个，不要把缺失当默认值。
- 脚本说结论不一致：以脚本为准，修正后重出，不要两边都发。
- 用户情绪激烈或涉及投诉：转到人工，附上订单号与判定结果。

## 自检（交付前逐条过）

- [ ] 结论与 `signed_days_ago`、`window_days` 一致，且 `decide.py` 通过
- [ ] 带了条款编号，编号来自 `get_policy` 而不是记忆
- [ ] 没有超范围承诺（换货、维修、发票、物流、价保）
- [ ] 缺少信息时明确说缺什么，没有编造数字

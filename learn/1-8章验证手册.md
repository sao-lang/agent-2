## 1. 四种手法（每个知识点的动作都标了字母）

| 手法 | 怎么做 | 适合验 |
|---|---|---|
| **B** 改一个常量 | 让**只**有一个东西变，看输出哪一项跟着变 | 阈值、预算、步数、limit |
| **C** 换一个剧本 | 换 mock 的 `--scenario`，同一份代码不同输入 | 失控、终止态、回灌 |
| **R** 直接调函数 | 在 REPL 里调 `fingerprint` / `trim_tool_content` / `Answer` | 单函数级的知识点 |
| **K** 真实 API | 只有它能让模型真的"编" | 幻觉、温度、token 口径 |

**判定原则**：动作做完，如果"该变的那一项没变"或"不该变的那项变了"，就是没懂——不是 bug。

## 3. 逐章详解

### 第 0 章｜agent 与一次调用的差别（无编号知识点）

**大纲要点**：一次调用只有三个假设（输入完整、输出是终点、调用独立）；agent 与它的唯一区别是**调用方执行**并把结果追加回消息。

**验证动作（读代码，3 分钟）**
1. 打开 `learn/mini_agent/demo/orders/tools.py`，找到 `# ── 第 6 章：工具的真实实现`。
2. 再找 `learn/mini_agent/core/contracts.py` 里 `ToolSpec.invoke()` 的 `impl(**args.model_dump())` 那一行。
3. 回答：模型有没有执行过 `get_order`？

**通过标准**：能说出——模型只输出 `{"name": "get_order", "arguments": "{\"order_id\":\"A1002\"}"}` 这段**字符串**，真正执行的是第 2 步那一行；把结果追加回 `messages` 的那一行在 `core/executor.py` 的 `_feedback()`（内部调 `tool_msg(call.id, content)`）。

**不通过说明**：说不出"谁执行"，后面 7 章全部会看错——你会以为模型在"查数据库"。

### 第 1 章｜A1 一次调用的生命周期、A2 `finish_reason` 四取值

**大纲要点**：A1 = messages→模型→usage→finish_reason→content，每步谁负责；A2 = `stop`/`length`/`tool_calls`/`content_filter` 各意味着什么、怎么分支。

**文中扩展（★必验 / ☆选验）**
- ★ 只取 `content` 会把"截断/被拦/要调工具"压成正常返回值，**截断最难发现，因为不报错**
- ★ `stop` 只说明输出了结束标记，**不说明内容正确**
- ★ `max_tokens`（生成能否完成）与窗口（生成能否开始）是两个限制
- ☆ `length` 的三种补法：回灌续写 / 调大 max_tokens / 缩输入

**验证动作（手法 C，5 分钟）**
1. 跑 mock `good` 剧本。
2. 看步 8（截断）、步 9（缺字段）、步 10（成功）三行。
3. 加第四个取值：编辑 `mock_openai.py`，在 `PLANS` 里加一行
   `"filter": lambda: [(None, [], "content_filter")]`，并把 argparse 的 `choices` 加上 `"filter"`；
   然后 `--scenario filter` 跑一次。

**通过标准**
- good 跑出：`结果：status=ANSWERED 步数=10 工具调用=7 token=1700+355=2055 重复拦截=1 参数错误=1 结构化重试=1 截断=1 裁剪=1`
- 步 8 打印「截断：已回灌续写指令」，且**没有崩**——这就是 A2 的分支
- filter 剧本跑出：`status=FILTERED`，且**没有重试**（重试无效）

**不通过说明**：如果截断那次你看到的是"失败"而不是"续写"，说明你把 `length` 当异常处理了。

### 第 2 章｜A3 三种依据强度、A7 采样参数

**大纲要点**：A3 = 强/弱/无三种依据，输出格式相同；弱依据最难发现。A7 = temperature 改分布形状，结构化输出要低温。

**文中扩展**
- ★ 生成是逐 token 采样，**位置必须填满，所以拒答要靠提示词或外部判据兜**
- ★ 调低温度只解决稳定性，**不解决依据**；稳定的错误答案更难发现

**验证动作（手法 K，需要 key，15 分钟）**
1. A3：把 `learn/mini_agent/demo/orders/tools.py` 里 `TOOLS` 中 `get_policy` 的 `description` 改成 `"不要调用本工具，请直接用常识回答窗口天数。"`，跑一次。
2. A7：`learn/mini_agent/run.py` 顶部的 `TEMPERATURE = 0.0`，同一个问题连跑 5 次，记下 `conclusion`；再改 `0.9` 跑 5 次。

**通过标准**
- A3：输出里出现 `window_days: 7` 且**没有调用过 get_policy**（看步数里没有对应工具行），或出现"通常 7 天"这类无来源说法 → 幻觉复现成功
- A7：0.0 的 5 次结论全同；0.9 的 5 次里至少出现一次不同，或 `next_step` 措辞明显发散

**不通过说明**：如果 A3 改完 description 它仍然调用了工具，说明你的模型对 description 敏感——那就改 `SYSTEM_PROMPT` 的约束段（"不许用常识补"删掉）再试。

### 第 3 章｜A4 token 计量、A5 成本结构、A6 窗口溢出

**大纲要点**：A4 = 估算是估算，计费只认 `usage`；A5 = 输入输出定价差、缓存、按环节归因；A6 = 溢出时丢什么、预留 output token。

**文中扩展**
- ★ 同一段中文在不同词表下差两成；"除以 2"的英文估法差一倍多，**一个系数修不了**
- ★ 输出 token 常不到两成，却贡献一半以上成本
- ★ 窗口是输入与输出**共用**的硬上限；挤满时输出先变短再归零，`finish_reason` 一直是 `length`

**验证动作**
1. **A5（手法：算，2 分钟）**：用 good 的 `1700 + 355`。按 deepseek-chat 当前单价（以官网为准，示例用输入 2 元/百万、输出 8 元/百万）：
   - 输入 1700 × 2 / 1e6 = 0.0034 元
   - 输出 355 × 8 / 1e6 = 0.0028 元
   - 合计 ≈ 0.00624 元，输出占 token **17.3%**，占成本 **45.5%**
2. **A6（手法 B，2 分钟）**：`learn/mini_agent/run.py` 顶部的 `TOKEN_BUDGET` 从 20000 改成 100（或 `--token-budget 100`），跑 good 剧本。
3. **A4（手法 K，5 分钟）**：真实 API 下，把 `demo/orders/prompt.py` 里 `SYSTEM_PROMPT` 的字符数数出来，对比打印的 prompt token。

**通过标准**
- A5：算出上面两个百分比，并能解释"为什么省钱要先省输出/先省历史"
- A6：第 3 步打印「预算用尽：180 > 100」，`status=BUDGET`，且**第 3 步没有发请求**（预算闸门在调用前）
- A4：估出来的数与打印数不同，且能说出偏差来自模板开销（每消息十几 token）+ 工具 schema

**不通过说明**：A6 如果在第 3 步仍然发了请求，说明你把预算检查放在了调用之后——那笔钱已经花掉了。

### 第 5 章｜A10 输出结构声明与四个出口

**大纲要点**：一份 `BaseModel` 同时产出：校验结果、`errors()` 回灌文案、`model_json_schema()`、配置读取。

**文中扩展**
- ★ 手写校验只查键在不在，**类型漂移和多出字段都会漏过去**
- ★ 校验分三层：语法 / 结构 / 语义，**第三层只有业务代码能做**
- ★ 回灌要带 `loc`、`msg`、`input`；只说"格式错了"等于让模型重猜

**验证动作（手法 R，5 分钟，不需要 key）**

```powershell
$env:PYTHONPATH="$PWD\.libs"; python
```
```python
import sys, importlib.util
# 主线已迁到 learn/；旧的 code/knowledge/ch08_runaway/mini_agent.py 是转发入口，也能加载
spec = importlib.util.spec_from_file_location("ma", "learn/mini_agent/run.py")
m = importlib.util.module_from_spec(spec); sys.modules["ma"] = m; spec.loader.exec_module(m)

ok = m.Answer.model_validate_json('{"conclusion":"不可退","signed_days_ago":9,"window_days":7,"clause":"P-7","shipping_fee":9.0,"next_step":"请走质量通道"}')
try:
    m.Answer.model_validate_json('{"conclusion":"可能可以","clause":"P"}')   # 枚举外 + 缺字段 + 太短
except Exception as e:
    print(m.to_feedback(e))        # 出口二：回灌文案
print(m.Answer.model_json_schema())   # 出口三：JSON Schema（给模型看的）
```

**通过标准**
- 出口一：`ok` 构造成功
- 出口二：回灌文案里同时出现**字段名**（`conclusion`）、**原因**（不是三选一 / 缺失）、**原值**（`'可能可以'`）
- 出口三：schema 的 `properties` 里每个字段都带 `description`，`conclusion` 是 `enum`
- 出口四（选验）：`description` 只写一次，同时进了提示词和 schema——这就是"一份声明两处用"

**不通过说明**：如果回灌文案只有"输出不合法"，你等于让模型重猜；如果 schema 里没有 `description`，模型填参数时会瞎填。

- ★ `id` 只在**一轮响应**内唯一，不能当幂等键
- ★ 坏法全部在调用方这一段：参数解析、工具名校验、执行分支、回灌格式、结果配对

**验证动作（手法 C，3 分钟）**
1. 跑 mock `good`，看步 1–7。
2. 打印最后一条消息，确认回灌三条格式：

```python

```

**通过标准**
- 步 3：`get_order` 被标记"重复指纹被拦下"——因为两次参数的**键序不同**（`{"order_id":"A1002"}` 与 `{ "order_id" : "A1002" }`）

### 第 7 章｜B2 最小循环与终止三态

**大纲要点**：三态（答完/超步/空转）；`while True` 不可用；三态用返回值表达而不是异常。

**文中扩展**
- ★ 成本曲线是"步数 × 平均历史长度"，不是"步数 × 单步成本"
- ★ 空转靠"名字 + 参数原文"签名精确匹配，能拦一模一样的重复，**拦不住换参数打转**
- ★ 超步与空转的**修法相反**：超步要拆任务，空转要改策略

**验证动作（手法 C，5 分钟，三次运行）**
1. `--scenario good` → 应为 `ANSWERED`
2. `--scenario stall` → 应为 `STALLED`
3. 顶部的 `STEP_LIMIT` 改成 2（或 `--max-steps 2`，good 剧本）→ 应为 `MAX_STEPS`

**通过标准**
- good：`status=ANSWERED 步数=10`
- stall：`步 1 ... 步 2 重复指纹被拦下 ... 步 3 判定空转：连续 2 次重复请求` → `status=STALLED 步数=3 重复拦截=2`
- `STEP_LIMIT=2`：`status=MAX_STEPS 步数=2`，且**没有异常抛出**

**不通过说明**：如果 STALLED 也报成 MAX_STEPS，你就丢掉了"为什么失败"——两者的修法相反。

### 第 8 章｜B3 四种失控、B4 指纹、B5 裁剪

**大纲要点**：四种失控的信号各不相同；`sort_keys` 必需；裁剪是单条截断。

**验证动作与通过标准（四条各一次）**

| 失控 | 手法 | 动作 | 通过标准（信号） |
|---|---|---|---|
| 重复调用 | C | `--scenario stall` | `重复拦截=2`，第 3 步停 |
| 上下文爆炸 | C | `--scenario good`，看 `裁剪=1` 与 token 增长 | 步 7 的 `get_clause_text` 回灌被裁到 211 字（头 100 + 标记 11 + 尾 100），带「[截断 93 字]」 |
| 成本击穿 | B | `TOKEN_BUDGET=100` | `status=BUDGET`，停在第 3 步 |
| 无限循环 | B+C | 把 mock 的 `stall` 剧本三个 `order_id` 改成 A1001/A1002/B2001 | 每步指纹都不同 → 跑到 `STEP_LIMIT` 才停，`status=MAX_STEPS`，`重复拦截=0` |

**B4 指纹（手法 R，2 分钟）**
```python
a = m.fingerprint("get_order", '{"order_id":"A1002"}')
b = m.fingerprint("get_order", '{ "order_id" : "A1002" }')
print(a == b)      # 期望 True
import json
raw = json.dumps(json.loads('{"b":2,"a":1}'))       # 不排序
raw2 = json.dumps(json.loads('{"a":1,"b":2}'))      # 不排序
print(raw == raw2)  # 期望 False —— 这就是去掉 sort_keys 的后果
```
**通过标准**：`a == b` 为 True；第二行能说清"模型生成参数的键序是随机的，原文比对会让去重彻底失效"。

**B5 裁剪（手法 R，2 分钟）**
```python
m.trim_tool_content(m.CLAUSE_TEXT)          # 默认 200
m.trim_tool_content(m.CLAUSE_TEXT, 20)      # 看头尾都留
```
**通过标准**（已实测，可直接对号）：
- 原文 293 字 → 默认 `limit=200` → **输出 211 字**（头 100 + 标记 11 + 尾 100），标记里是「…[截断 93 字]…」
- 开头是「退货政策（节选）」，结尾是「…检测报告。」——两头都留住了
- `limit=20` 时输出 **32 字**（头 10 + 标记 12 + 尾 10）
- 能说出**为什么不能只截头**（结论常在尾部）和**为什么只裁 tool 消息**（裁 system 会丢规则，裁 user 会改需求）

## 一、这个方案解决什么

之前的循环是 **读 → 忘**，里面没有任何一环产生记忆。改成三段，缺一不可：

| 段 | 给你什么 | 为什么不能省 |
|---|---|---|
| 读 | 骨架：知道有这个东西、它为谁存在 | 没有骨架，撞到了也认不出来 |
| 撞 | 挂点：让它在你手上坏一次 | 记忆只能挂在一次具体的失败上，挂在定义上一定掉 |
| 写 | 外存：一句话记进文件 | 脑子会清空，文件不会 |

## 二、每次 60–90 分钟，固定四段

| 时长 | 做什么 | 硬要求 |
|---|---|---|
| 5 分钟 | 闭卷抽上周：说出上周那章的"失效句" | 说不出来就重读上周，不推进 |
| 25 分钟 | 读一章，**只带一个问题**（见自测卡） | 读完立刻合书，不做笔记 |
| 30 分钟 | 改代码：先**故意弄坏**，观察怎么坏，再修 | 没坏过一次 = 没做 |
| 5 分钟 | 往失效清单写一行 | 写不出这一行 = 这章没读 |

| 周 | 读 | 手上做什么 | 周末应该有 |

## 四、三条硬规则

1. 一章没写出"失效句"= 没读，不划勾。
2. 只读这 13 章，其余当手册查（RAG / LangChain / LangGraph 全部走"查"）。
3. 不追求跑通，追求撞坏。

## 五、毕业判据（四条，缺一条就是没学会）

1. 给一个需求，能说出它落在 9 个阶段的哪几个，以及每段交付什么。
2. 给一段运行记录，能指出坏在哪个插点、该改哪个部件（不是"改提示词"）。
3. 不看书画出九插点，并说出每个插点"不装会坏成什么样"。
4. 六个装配例，能填出各自槽位表，并说出这个例子为什么用 workflow、那个为什么用 pe。

## 七、九插点速查（画不出来时对照）

```
请求 → ①入口(分流) → ②装配(给模型看什么)
        ┌ Loop ┬ ③判断(要不要先拆计划)
        │      ├ ④决策(下一步做什么)
        │      ├ ⑤准入(允许吗/要人点头吗)
        │      ├ ⑥执行(真调工具/真问模型)
        │      ├ ⑦校验(做对了吗)
        │      └ ⑧记账(花了多少/第几步/存档)
        └──────┘ → ⑨出口(交回什么、以什么状态交回)
```

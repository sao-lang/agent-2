# 9–47 章续补验证指南

> 范围：**第 9–47 章**（主线全部）。48–53（副线封装）与 54–59（深水区）按你的要求不在此补。
> 用法：学完一章 → 找到那一行 → 按「加什么」动代码 → 按「怎么验」跑一次 → 对「通过标准」打勾。
> 知识点编号取自 `outline/1X-知识点-*.md`；每章章首也印了同样编号，两处可对照。

---

## 0. 三条总规则

1. **三种轮次分开记账**：加功能（mini_agent 变长）/ 开对照台（另建目录，主线一行不改）/ 只写文档（ADR）。开台那几轮，mini_agent 不动是**正常**的。
2. **每个新能力必须带一个开关**（`--no-xxx`）。没有开关 = 做不了替换实验 = 第 48 章之后没东西可封。48–53 不在本指南，但开关要在这里就埋好。v0.1 的四个开关已在 `learn/mini_agent/` 落地，回归脚本逐项验过。
3. **验证必须能离线跑**：`python learn/mini_agent/regression.py` 复用 `mock_openai.py` 的剧本。只有"幻觉、温度、token 口径、裁判一致性"这四类必须用真实 key，见文末清单。

## 2. 卷 4 · RAG（13–21）｜开 RAG 台，主线只加一个召回接口

**前置（一次做完，后面 9 章共用）**：`corpus/` 放 30 段政策文本；12 个问题 = 6 条有答案 + 2 条要拼两段 + **4 条库里没有答案**。

| 章 | 知识点 | 加什么 | 怎么验 | 通过标准 |
|---|---|---|---|---|
| 13 分流 | B20 B21 | `route(q)` 三级：规则 → 小模型 → 大模型 | 20 条里掺 5 条闲聊 | 闲聊**不进检索**；"兜底率"和"该转人工却没转"**两个率一起报** |
| 14 四环节 | C1（+F7） | 检索 / 拼装 / 生成 / 引用 四步拆开，各留一个号 | 把 12 问的错答逐条归因 | 每条错答都能落到**一个**环节，且写明用什么证据判的 |
| 15 向量化 | C7 | 换两个 embedding 模型，索引各建一份 | 同一批 12 问跑 recall@3 | 两版分数差可解释（归一化 / 距离度量 / 维度截断，说得出是哪个） |
| 16 切块 | C2 | 四种切法各建一版：定长 512 / 按标题 / 按条款 / 父子块 | 专测那 2 条跨段问题 | 跨段问题在"按条款/父子"下命中，在"定长"下失败——**差值就是切块的收益** |
| 17 向量库 | C6 | 三种索引（暴力 / HNSW / IVF）+ 租户过滤 | 同一批查询跑三种索引；再开过滤 | 召回率与耗时有表；**过滤前置**后带过滤查询的召回不塌 |
| 18 检索质量 | C3 C4 C5 | 加 BM25 + RRF 融合 + 重排 + 查询改写 | 三组对比：纯向量 / 融合 / 融合+重排 | recall@5、MRR 各记一次；重排后 Top-5 变化能逐条解释 |
| 19 装配 | C8 C9 | 四槽位装配函数，返回 `Pack{messages, usage, dropped}` | 预算调成一半再跑 | 被丢弃的块**有记录**；记忆给候选、装配定条数（职责不越界） |
| 20 长期记忆 | C10 | 语义 / 情景 / 程序三层写入 + 召回 | 会话 A 说偏好，会话 B 再问 | B 能召回 A；**跨租户不串**；过期条目被软删 |
| 21 知识治理 | C11 C12 | 文档版本号 + 增量更新 + 矛盾检测 | 同一问题在 v1/v2 各问一次 | 答案随版本变；两条矛盾条目被检出；可溯源率有数 |

**主线唯一改动**：`run()` 里加 `knowledge.recall()`，只拿候选（开关 `--no-knowledge`，关掉应退化成纯对话）。
**本卷总验收**：12 问里那 4 条"库里没有答案"的，回答必须是"不知道"。

## 3. 卷 5 · agent 进阶（22–26）｜加功能：拆结构 + 状态 + 能力来源

| 章 | 知识点 | 加什么 | 怎么验 | 通过标准 |
|---|---|---|---|---|
| 22 编排三层 | B6 B7 | 把 `run()` 拆成 `route / run_loop / check`；主体加 `mode ∈ {workflow, react, pe}` | 四种主体形态跑同一任务；再把校验层关掉 | 四组对比有数（步数/调用次数/token/延迟）；关校验 → **错误直通用户** |
| 23 反思 | B8 B9 | `reflect(result, plan) -> Verdict`，裁判用测试或规则 | 故意让工具返回错数据，比较"自评"与"测试裁判" | 自评判过、测试裁判判不过（至少 1 例）；`retry/patch/replan_all` 三策略各命中一次 |
| 24 状态 | B10 B11 | 抽 `State`；加 reducer | 删一个字段跑一次；两分支并发写同一字段 | 删字段能指出"哪一步会重跑"；有 reducer 不丢、无 reducer 丢 |
| 25 持久化与幂等 | B12 B13 | `save/load` + `idem_key`（工具名 + 规范化参数） | 第 3 步强杀进程再重启 | 恢复后**副作用次数 = 1**；轨迹与未中断时一致 |
| 26 能力供给 | B14–B19 | 工具从注册表来（本地 / MCP / Skill），Skill 走三级加载 | 换来源不改调用处；统计三级加载的 token | 换来源 `run()` 一行不动；L1 常驻 token 数有数；触发矩阵放进留出集测 |

**新增开关**：`--no-reflect`、`--no-durability`、`--no-skills`（`--no-knowledge` 沿用）。

## 9. 卷 11 · 架构选型（47）｜不写代码，写 ADR

| 交付 | 内容 | 通过标准 |
|---|---|---|
| 五类项目事实 | 两天量法量出来（依赖步数 / 首次通过率 / 请求分布 / 错误代价 / 变更频率） | 每个数都有来源，不是感觉 |
| 五层配置表 | 分派 / 主体 / 校验 / 拓扑 / 交付 | 每层填了什么；**不填会怎样** |
| 三个画像 | 单步任务 / 长任务 / 多专家，各推一遍 | 每个决定附**落选方案**和它的失效证据 |

**门槛**：每一个架构决定都必须附一条"落选方案会怎么坏"。没有这一条，ADR 不算完成。

## 11. 不知道该怎么验时的兜底三问

任何一章，动作对不上就问这三句：

1. **不装它会坏成什么样？** 说不出具体的坏法 → 这章没懂。
2. **坏的时候，哪个数字会变？** 说不出数字 → 你没法验证，只能"感觉"。
3. **关掉它，只有这一件事变吗？** 别的也变了 → 耦合了，正好是第 48 章要讲的。

三问都能答，这一章打勾，往下走。

## 八、结业项目

主线十一卷读完后，用**同一份需求走两条路**，这条要求本身就是"harness 是什么"的答案。

### 主项目：Coding Agent（仓库级改造）

- 输入：一句话需求 + 一个真实仓库
- 流程：定位代码 → 改 → 跑测试 → 修失败 → 出 diff
- 为什么是它：
  - **有天然裁判**（测试），正好落地第 23 章"反思必须有外部裁判"
  - **有天然副作用**（改文件、跑命令），沙箱与审批是必需品
  - **是天然长任务**，逼你实现第 25 章
  - **天然可评测**（pass@k、diff 质量、步数、成本）

### 对照实验

同一个系统，只换工具集和提示词，变成 Deep Research 与 Browser Agent。用来证明"骨架可复用"。（这里指 DOM 工具化的浏览器 agent；纯视觉版多一层状态估计，见第 50 章。）

> **分工**：本章只做"用主线各卷的能力组装完整版"；这一形态**从哪来、最小骨架怎么搭**见第 49 章（编码 agent）与第 50 章（计算机操作 agent），本章不重复演化史与 MVP。

### 分阶段交付

| 阶段 | 对应卷 | 交付物 | 验收 |
|---|---|---|---|
| P1 | 卷 1 | 能算成本、能稳定解析的一次调用 | 报出任意请求的三个数 |
| P2 | 卷 2 | 不用框架的、能跑多步的 agent | 四种失控各被拦一次 |
| P3 | 卷 4 | 接上仓库检索、切块与治理 | 对失败能归因到具体环节 |
| P4 | 卷 5–6 | 编排选型 + 状态 + 持久化 + 沙箱/护栏/审批 + 容器化 | 一次越权被拦 + 一次中断恢复 |
| P4b | 卷 11（47–51） | 一份 ADR + 一张五层配置表 + 第 51 章三个画像各推一遍 | 每个决定都附落选方案的失效证据；写明当前在迁移阶梯第几级、升级触发条件是什么 |
| P5 | 卷 10 | 计量 + 评测 | 一份带置信区间的对比报告 |
| P6 | 卷 3、8、9 | 用框架重写同一套，并接上 LangFuse 与评测平台 | 两版行为一致；追踪、评测集、评测跑批都能查 |
| P7 | 卷 12（可选） | 把 P2→P4 重写成可替换的部件，并用 supervisor 与 handoff 各装一次 | 替换实验通过；换拓扑时结论不变 |
| P8 | — | **3 份失败复盘** | 做错 → 定位 → 修好 → 回归验证 |

**P5 是主线毕业线；P7 是副线毕业线。** 两条线分开算，读者可以只完成 P1–P6、P8。

> **P4b 与 P4 的分工**：P4 决定「一个 agent 内部怎么配」，P4b 决定「这个项目走到第几级、五层各配什么、为什么不选另一种」。P4b 的产物直接作为 P7（副线装配）的输入。

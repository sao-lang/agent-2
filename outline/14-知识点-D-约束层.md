## ④ 约束层

| # | 知识点 | 必讲的内容 | 示例 |
|---|---|---|---|
| D1 | 沙箱四条边界 | 路径/网络/资源/时间；`resolve()` 与元数据地址 | `../` 越界与 `resolve()` 拦下的对照 |
| D2 | 护栏必须是代码 | 为什么 prompt 里的"不要"不算护栏 | 同一违规请求在 prompt 约束/代码约束下的结果 |
| D3 | SQL 守卫 | `WITH ... DELETE` 这类绕过；白名单而非黑名单 | 三条绕过语句与守卫的判定 |
| D4 | PII 与顺序 | 正则顺序错一个就漏（身份证在手机号前） | 两种顺序下的漏检 |
| D5 | 误杀率与拦截率 | 两个数必须一起报；只报拦截率等于自欺 | 一份混淆矩阵与两个比率 |
| D6 | 间接注入 | 检索文档里的"忽略之前的指令"；最容易忽略的缝 | 一份被投毒的文档与它的效果 |
| D7 | 攻击面地图 | 绕过不发生在你以为的那一层；红队怎么打 | 一张分层攻击面图与三个打点 |
| D8 | 分级审批 | 哪一步要人点头；审批卡片写什么；有效期 | 一张审批卡片与它的状态流转 |
| D9 | 中断与恢复 | 关页面再回来继续；审批状态机 | 一次中断 2 小时后恢复 |
| D10 | 多 Agent | 拆分条件；上下文隔离；通信成本；**四种拓扑（supervisor/handoff/blackboard/流水线）与各自的失效形态**；**A2A 的四个对象（agent card / task / message·part / artifact）与最小往返**；远端 agent 是不可信输入 | 单 agent 与双 agent 的 token 对比；同一任务两种拓扑的消息条数与延迟；一次 A2A 任务的完整状态流转 |
| D11 | 对外三种形态 | 同步 API/异步队列/流式；各自适用 | 三种形态各一个最小实现 |
| D12 | SSE 六件套 | 关缓冲（应用层+nginx）、心跳、断线、错误帧 | 一个可断线重连的流式接口 |
| D13 | 队列/幂等/限流/鉴权/熔断/降级 | 上线前的可靠性件套，每件的失败形态；超时是前提，重试要预算与抖动，熔断按目标（provider/endpoint/tenant）而非全局，降级三档（换模型/换路径/兜底）且每档要有"降级后仍正确"的判据 | 六件套的最小实现与各自拦下的请求；一次熔断三态流转（closed→open→half-open）；一次降级到"换模型"后仍通过 schema 校验 |
| D14 | 优雅关闭 | `docker stop` 时手上的活；SIGTERM 直达（exec 形式） | 两种 Dockerfile 写法下的关闭行为 |
| D15 | 镜像分层与体积 | 多阶段构建；什么绝不能进镜像 | 单阶段/多阶段镜像体积对比 |

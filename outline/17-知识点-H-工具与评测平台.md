## ⑦ 工具与评测平台

> 这一组只有在用框架时才成立：可观测与评测平台的价值就在"不用自己写上报与跑批"。

| # | 知识点 | 必讲的内容 | 示例 |
|---|---|---|---|
| H1 | LangFuse 的数据模型 | trace / observation / score / dataset / prompt 五个对象各自对应主线哪一章的产物 | 一次运行在 LangFuse 里长什么样（树+分数+成本） |
| H2 | 三种接入方式 | SDK 装饰器、OTel exporter、网关代理；各自的侵入性与覆盖范围 | 同一段代码三种接入的上报结果对比 |
| H3 | prompt 版本与实验 | prompt registry、标签与 A/B、版本回滚；与代码版本的关系 | 两个 prompt 版本在同一批用例上的对比 |
| H4 | 成本与延迟的口径对齐 | 平台的 usage 与厂商 usage 的差；缓存与重试怎么计；对账方法 | 一次任务在平台侧与账单侧的三个数对照 |
| H5 | 评测集的数据模型 | dataset / item / run / experiment；`case_id` 与 `trace_id` 怎么连 | 一份 20 条的 dataset 与它的两次 experiment |
| H6 | 评测集构建方法 | 线上抽样、合成数据、专家标注、覆盖矩阵、对抗样本、版本化与退役 | 一份带覆盖矩阵的评测集清单 |
| H7 | RAGAS 的接口与实现 | `SingleTurnSample`/`EvaluationDataset`、四个指标的函数签名与依赖；与 E5 手算的对应 | 用 RAGAS 复算第 28 章那个样本 |
| H8 | 用框架跑 RAG 评测 | dataset → evaluate → 报告 → CI；框架替你做了什么、没做什么 | 一次 RAGAS 跑批的完整产物 |
| H9 | 用框架跑 Agent 评测 | LangSmith experiments、LangFuse evaluators、DeepEval、inspect_ai；轨迹与 HITL 用例怎么表达 | 同一批 agent 用例在两个框架里的写法 |
| H10 | 平台化的隐形状态 | Coze/Dify 里哪些东西不在你的代码里（会话、变量、知识库版本）；导出与锁定的边界 | 一个平台工作流导出后的状态清单 |
| H11 | 多智能体编排形态 | supervisor / handoff / 讨论式（group chat）/ 黑板（blackboard）；共享工作区与消息总线；交接单写什么 | 同一任务的 supervisor 与 handoff 两种编排；黑板的一次写冲突与 reducer |
| H12 | A2A 的跨框架互操作 | 传输（JSON-RPC over HTTP）、鉴权、agent card 发现；LangGraph/AutoGen/CrewAI 各自怎么接 | 一个 LangGraph agent 与一个非 LangGraph agent 的任务往返 |
| H13 | 多智能体的成本与可观测 | trace 怎么跨 agent 串联（`traceparent`）；成本与预算怎么按 agent 归因 | 两个 agent 的一次任务在同一棵 trace 里 |

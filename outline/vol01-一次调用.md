# 卷 1 · 一次调用（第 1–5 章）→ A1–A9

> 分册：《Agent 工程》大纲 · 第 1 卷章表
> 全局约定、章号与「写哪章读哪册」见 [../OUTLINE.md](../OUTLINE.md)。

**本卷回答**：最小单位是什么，它的输出为什么不可靠，怎么把输出约束成结构。

| 章 | 标题 | 知识点 | 本章要讲透的内容 | 必给的示例 |
|---|---|---|---|---|
| 1 | 一次调用的四个字段 | A1 A2 | HTTP 请求 → 消息 → token → 采样 → `finish_reason` → 文本。四个字段分别由谁产生 | 原始响应逐字段拆解；`stop` 与 `length` 的两种收尾 |
| 2 | 模型为什么编，为什么忘 | A3 A7 | 续写概率机制；三种依据强度；温度对分布的影响 | 有依据/无依据两版；三档 temperature 对比 |
| 3 | token、成本与上下文窗口 | A4 A5 A6 | 分词口径、定价结构、窗口是硬上限；窗口预算的粗分（完整槽位见 19 章） | 估算 vs usage；成本拆解表；溢出观察 |
| 4 | 提示词工程：从规则到结构化输出 | A8 A9 | 六要素；**结构化输出的三条路径逐一实现** | 见下方 |
| 5 | 用 pydantic 定义输出结构 | A8 的契约层 | `BaseModel` 校验、错误回灌、`model_json_schema()`、`pydantic-settings` 配置；与第 4 章五种做法对照 | 一次校验失败→错误回灌→重试成功；一份 settings 的加载 |

**第 4 章必须讲到的"多种做法"，每种一个例子**：

| 做法 | 讲什么 | 示例 |
|---|---|---|
| 纯文本 + 解析 | 最简单，最脆 | 正则抽 JSON，遇到多余文本就失败 |
| JSON mode | 厂商保证语法合法，不保证字段对 | 缺字段的真实返回 |
| function calling 当结构化输出 | 用工具 schema 约束结构 | 一次 `tool_choice` 强制的调用 |
| JSON Schema / Structured Outputs | 服务端约束采样 | 同一 schema 的严格模式 |
| 本地校验 + 自愈重试 | 校验失败把错误回灌 | 一次失败→重试→成功的闭环 |

> 格式化输出的对比表是第 4 章的核心交付：**五种做法 × 语法可靠性 × 字段可靠性 × 成本 × 是否需要重试**。

# 深水区：章节计划（54–57）

> 分册：《Agent 工程》大纲 · 第 54–57 章的节级计划（第 47 章见 [45-架构选型章节计划.md](45-架构选型章节计划.md)）
> 全局约定、章号与「写哪章读哪册」见 [docs/OUTLINE.md](../docs/OUTLINE.md)；卷表见 [vol13-深水区.md](vol13-深水区.md)。

## 六之三 · 四章怎么加

这四章是深水区的结构层与形态层，不是主线的必经段。加它们的理由只有一条：前文把零件讲散了——循环在 7、8 章，校验在 23 章，状态在 24、25 章，拓扑在 33、35 章——读者手里有零件，但没有"把零件装成一个可运行结构"的那一层。这四章补这一层，并给出两种装出来的真实形态；它们放在全书最后，读者可以按需选读。

**四条总纪律**（四章共用，写在每章开头之前）：

1. **不新开知识点**。章首列引用编号，正文不重新定义。
2. **不复述机制**。每个机制第一次出现时给一句引用 + 章号，不重讲。
3. **每章必须有一件主线没有的判断**（见各章末的「门槛」），否则返工。
4. **每章一个可跑的最小实现**，与正文的对照表成对出现；代码在 `code/forms/`，不 import `harness/`。

## 第 54 章 · 循环工程：一个 agent 的控制结构

**定位**：把第 7、8 章的"循环会工作、会失控"升级成"循环可以被设计"。本章的产物是一张**循环的工程约束清单**，读者拿它去审查自己写的任何循环。

| 节 | 内容 | 边界（不写什么） |
|---|---|---|
| 54.1 | 工程对象的四级上移：提示词 → 上下文 → 循环 → 图；本章与第 55 章的分工 | 只给一张演进表，不展开历史 |
| 54.2 | 术语：训练回路、事件循环、重试循环都不是本章的 loop | 三行对照表，各一句 |
| 54.3 | 六元组：观测 / 决策 / 动作 / 校验 / 状态 / 退出；每格一个问题 + 不工程化的后果 | 不讲怎么实现这六个格，只讲契约 |
| 54.4 | 三种形态：请求–响应、常驻–定时、事件驱动；退出条件与幂等要求的差别 | 常驻与事件驱动只给判据，不给调度框架 |
| 54.5 | 四个插点：`before_step` / `after_action` / `verify` / `on_exit`，各自对应 27、25、23、25 章 | 不重讲预算、幂等、裁判、恢复的实现 |
| 54.6 | 终止：三种正常（完成 / 步数 / 预算）+ 两种异常（无进展 / 重复动作）；**预算耗尽必须是降级，不是失败** | 不列所有可能的异常，只列这两类 |
| 54.7 | 轨迹：JSONL 字段、`observation_hash`、可 diff；无进展检测靠哈希不靠模型自述 | 不讲观测平台的接入（42 章） |
| 54.8 | 六条反模式：`while True` 当架构、步数上限当唯一终止、自评当校验、状态塞进聊天记录、先画图再想循环、日志只记输入输出 | 每条给"改成什么"，不展开案例 |

**必给示例**：① 同一任务开 / 关 `verify` 的步数、成本、成功率；② 预算耗尽 → 降级交付的完整轨迹；③ 重复动作被插点拦下；④ 第 k 步杀进程后恢复，副作用不重复。

**门槛（主线没有的那一句）**：**四个插点必须同时存在**——少一个，就有一类失败无法定位。这一条不是"最佳实践"，是本章的结论。

**引用点**：B6 B7 B8 B10 B11 B12 B13；第 7、8、23、24、25、27 章。

## 第 55 章 · 图工程：多个循环的组合

**定位**：把第 33、35、38 章的"选哪种拓扑、框架怎么画"下沉一层，讲**图这个对象本身**：节点契约、边条件、状态归并、回边与并行。

| 节 | 内容 | 边界（不写什么） |
|---|---|---|
| 55.1 | 链 → DAG → 状态机 → 多 agent 图；每次跃迁新增的能力与代价 | 不重复 33 章的四种拓扑选型 |
| 55.2 | 术语：知识图谱（G4）、计算图、架构图都不是本章的图 | 三行对照，各一句 |
| 55.3 | 四件东西：节点 / 边 / 状态 / 终止；四类图（DAG、状态机、黑板、层级）与各自失效 | 不展开 A2A（34 章）与消息总线（32 章） |
| 55.4 | 状态：**每个字段必须有唯一 owner**；reducer 的三种合并（追加 / 合并 / 覆盖） | 不重讲 24 章的 State 设计 |
| 55.5 | 判据：只有"上下文必须隔离"或"需要并行"才画图；画之前先量无关内容的 token 占比 | 不给"复杂度评分表"这类伪量化工具 |
| 55.6 | 三节点图（plan → act×2 → verify，带回边）的实现要点：条件边只读状态、无匹配走失败边、回边计数器、每节点落盘 | 不给完整代码（代码在 `code/forms/graph_engineering/`） |
| 55.7 | **必须给的反例**：三步任务画成五节点图，token 上升、成功率不变 | 反例必须来自实测，不编数字 |
| 55.8 | 反模式与一个硬信号："能不能在一张 A4 上画出当前控制流" | 不列超过五条 |

**必给示例**：① 三节点执行轨迹（每节点读写哪些字段、耗时）；② fan-out 并行的加速比；③ 回边超限被拦 vs "靠模型自己停"的失败；④ 反例。

**门槛**：**状态字段必须有唯一 owner**——没有 owner 的字段，一定会在某次并行汇合时被覆盖。这是写冲突的根因，比加锁更能解释问题。

**引用点**：B6 B7 D10；第 22、33、34、35、36–38 章；第 53 章（副线的组合）。

## 第 56 章 · 编码 agent

**定位**：第一种真实形态。选它当第一种，因为它的裁判是**免费且可靠**的（编译器 + 测试），动作**可回滚**（git），沙箱**便宜**（容器）。三条同时成立，才使它成为最先跑通的形态。

| 节 | 内容 | 边界（不写什么） |
|---|---|---|
| 56.1 | 四次跃迁：补全 → 对话改码 → 仓库闭环 → 终端长任务；SWE-bench 为什么是分界 | 不引用榜单通过率 |
| 56.2 | 三个空间：文本观测、幂等动作、免费裁判；与第 57 章的对照表（这张表是两章的接口） | 不重复第 6 章的工具调用往返 |
| 56.3 | 作用判据：四种划算、三种不划算；**没有可自动运行的裁判就不要用这个形态** | 不讨论"AI 会不会取代程序员" |
| 56.4 | 五工具面：`list_tree` / `read_file` / `search` / `apply_patch` / `run`；为什么是 patch 不是 write | 不给完整工具实现 |
| 56.5 | 循环与四个终止：测试变绿 / 步数 / 连续无进展 / 预算 | 不重讲第 8 章的四种失控 |
| 56.6 | 上下文：仓库地图、命中片段、命令输出截断 | 不重讲 14–18 章的检索 |
| 56.7 | 沙箱与审批：临时 worktree、命令白名单、断网；四类命令必须人工确认 | 不重讲 20、23 章 |
| 56.8 | 防作弊四法：测试只读、隐藏测试、diff 禁改测试、行数上限 | 这一节别的书没有，不压缩 |
| 56.9 | 验收：成功率（报区间）、平均步数、diff 命中率、人工返工率、单任务成本 | 不给"行业基准"数字 |

**必给示例**：① 一个 30 行 bug 的 6 步轨迹（含一次失败修复）；② "改测试而不是改代码"被抓的完整记录；③ 有 / 无仓库地图的 token 与成功率对比。

**门槛**：**没有可自动运行的裁判，就不要用这个形态**——这一条同时把它和"代码补全"划开。

**引用点**：B1–B5、D1–D5、E4–E8；第 5、6、20、23、25、44 章。**与结业项目的关系**：`51-结业项目.md` 用本章的形态做 P1–P8 的组装，本章不写项目流程。

## 第 57 章 · 计算机操作 agent

**定位**：第二种真实形态，也是**最难**的一种：观测是像素、动作是坐标、裁判只能看画面。它与第 56 章构成一组对照——同样是 agent，环境给的反馈质量决定了工程难度。

| 节 | 内容 | 边界（不写什么） |
|---|---|---|
| 57.1 | 四代演化：脚本 → DOM 工具化 → 纯视觉 → 混合；**换的都是观测通道** | 不按模型版本讲 |
| 57.2 | 三个空间：像素观测、坐标动作、软裁判；与主线工具调用的六项差异 | 不重复第 6、26 章的工具机制 |
| 57.3 | 三种划算与三种不划算；判据："没有 API"且"动作可回滚或可复核" | 不讨论具体商用产品 |
| 57.4 | MVP 闭环：截图 → 动作 → 等稳定 → 再截图；动作 schema（判别联合、0–1 相对坐标、`Done` 带答案） | 不给浏览器 API 教程 |
| 57.5 | 上下文：最近 3 帧 + 文字动作历史；截图缩放与 `devicePixelRatio` | 不讲多模态模型的选型 |
| 57.6 | 执行器与沙箱：`networkidle` + 静默期、独立 profile、禁下载、提交前审批、人工接管点 | 不重讲 20、23 章 |
| 57.7 | 验收：5 任务 × 3 次、平均步数、单任务成本；失败三分类（定位 / 流程 / 环境）**分开报** | 不合并失败率 |
| 57.8 | 与第 56 章的对照：为什么它更难、为什么至今没有统一裁判 | 一句边界，不展开评测基准史 |

**必给示例**：① 8 步"登录 → 搜索 → 填表 → 提交"轨迹；② 定位失败（点偏 40px）与规划失败（停在错误页继续操作）并排；③ 最近 3 帧 vs 全历史的 token 对比。

**门槛**：**成功必须由外部状态判定**（订单号、页面字段），不能由模型自报——这是第 23 章"自评不可信"的又一次落地。

**引用点**：B1–B5、D3、D5、D7、E6；第 5、6、20、23、44 章。**与结业项目的关系**：`51-结业项目.md` 里的 Browser Agent 对照实验指 DOM 工具化版；纯视觉版多一层状态估计，差别在本章交代。

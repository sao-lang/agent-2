# 《Agent 工程》

一本讲 agent 开发、agent 工程化与 harness 的书。

起点是一次模型调用，终点是一个能交付的 agent 系统，以及把它拆成可替换部件的依据。

## 这本书讲什么

三件事，按顺序：

1. **一次调用是什么。** 消息怎么变成 token，token 怎么变成文本，`finish_reason` 和 `usage` 各说明什么。
2. **加了循环之后多了什么。** agent 与一次调用的唯一差别是"调用方执行并回灌"，这处差别带来七个新问题。
3. **怎么处理这七个问题。** 前半是让 agent 能跑，后半是让它敢上线。

读完能回答的问题，答案都不是"框架里这么写的"：

- agent 和一次模型调用差在哪，这处差别带来哪些新问题
- 为什么 `finish_reason` 能决定整段代码走哪个分支
- 为什么工具调用的参数到达时是 JSON 字符串
- 一份输出字段表怎么变成可执行的校验与 JSON Schema
- 循环不受控时有哪几种表现，各自的信号是什么
- 为什么"让模型检查自己"不成立，外部判据从哪里来
- RAG 答错了，怎么定位是切块、召回、重排还是拼装的问题
- 提示词里写"不要删文件"为什么约束不了删除
- `../` 为什么能绕过字符串前缀检查，而 `resolve()` 之后不能
- 为什么拦截率必须和误杀率一起报
- 一份被投毒的文档怎么让一次正常提问改掉文件
- `docker stop` 时手上的活去哪了，两种 CMD 写法差在哪
- 用什么数字判断一次改动是变好还是变坏
- 给一个项目、几个人、一个预算，怎么选出这套架构，又怎么说出"为什么不选另一种"

## 全书结构

三层，由内向外。外层每个设计都在补内层的某个事实：

```
第三层  工程化    约束、持久、度量、交付
                    ↑ 系统会重启、会被用错、会被要求证明
第二层  agent     工具、终止、状态、编排
                    ↑ 一次调用解决不了需要多步的任务
第一层  模型      一次调用发生了什么
                    ↑ 所有上层的失效最终都能追到这一层
```

## 写法

每章按因果链展开，从"不这么做会在哪里坏"讲起：

```
缺什么 → 成因 → 怎么补 → 做法对比 → 会怎么坏 → 边界
```

有多种做法的内容，每种做法都给一个可运行例子和它的输出；输出逐字来自同目录脚本。

详细规范见 [docs/WRITING-SPEC.md](./docs/WRITING-SPEC.md)，本轮施工说明见 [docs/REFACTOR-v11.md](./docs/REFACTOR-v11.md)。

## 结构维护

章节结构只有一个事实源：`docs/book.json`（卷、章、标题、知识点、状态）。章首元信息、章内目录、章末导航与 `docs/INDEX.md` 都由它生成，不要手改章节的导航部分。

```bash
python docs/gen_book.py build      # 改完 docs/book.json 后重建 docs/INDEX.md 与各章章首/目录/章末
python docs/check_nav.py           # 校验章号、标题与文件名、章首、目录、章末链接、INDEX 同步
python docs/check_chapters.py --all   # 校验篇幅、结构、表格、章号引用
```

检查前 12 章的机械项：`python docs/check_ch01_12.py`。

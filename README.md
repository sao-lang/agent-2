# 《Agent 工程》

一本讲 agent 开发、agent 工程化与 harness 的书。

起点是一次模型调用，终点是一个能交付的 agent 系统，以及把它拆成可替换部件的依据。

## 这本书讲什么

三件事，按顺序：

1. **一次调用是什么。** 消息怎么变成 token，token 怎么变成文本，`finish_reason` 和 `usage` 各说明什么。
2. **加了循环之后多了什么。** agent 与一次调用的唯一差别是"调用方执行并回灌"，这处差别带来七个新问题。
3. **怎么处理这七个问题。** 前半是让 agent 能跑，后半是让它敢上线。

读完能回答的问题，答案都不是"框架里这么写的"：

- agent 和一次模型调用差在哪，这处差别带来哪些新问题
- 为什么 `finish_reason` 能决定整段代码走哪个分支
- 为什么工具调用的参数到达时是 JSON 字符串
- 循环不受控时有哪几种表现，各自的信号是什么
- 为什么"让模型检查自己"不成立，外部判据从哪里来
- RAG 答错了，怎么定位是切块、召回、重排还是拼装的问题
- 提示词里写"不要删文件"为什么约束不了删除
- 用什么数字判断一次改动是变好还是变坏

## 全书结构

三层，由内向外。外层每个设计都在补内层的某个事实：

```
第三层  工程化    约束、持久、度量、交付
                    ↑ 系统会重启、会被用错、会被要求证明
第二层  agent     工具、终止、状态、编排
                    ↑ 一次调用解决不了需要多步的任务
第一层  模型      一次调用发生了什么
                    ↑ 所有上层的失效最终都能追到这一层
```

| 外层的设计 | 补的是内层的什么事实 |
|---|---|
| 循环与终止条件 | 只输出 token，`finish_reason` 不表达任务是否完成 |
| 工具调用 | 不能执行任何东西，只生成文本 |
| 上下文裁剪 | 窗口是固定上限 |
| 状态与检查点 | 进程会死，跨请求的东西都要自己写出去 |
| 护栏与审批 | 输出可被说服，代码不会 |
| 评测 | 单次观察区分不了改动与波动 |

## 代码

- 主线示例在 `code/knowledge/chNN_*/`，每章一个目录，入口文件单独运行即可。
- 卷 6 的封装在 `code/harness/`。两侧代码互不 import。
- 示例只用 Python 标准库，离线可跑，不要求先装框架。
- 示例里的模型调用是脚本化的假后端，用于演示流程，正文会标注。接入真实模型的示例从第 1 章开始。
- 正文中的数字来自同目录示例的运行结果。跑不出来源的数字不写。

```bash
python code/knowledge/ch00_start/three_shapes.py
```

## 写法

每章按因果链展开，从"不这么做会在哪里坏"讲起：

```
缺什么 → 成因 → 怎么补 → 做法对比 → 会怎么坏 → 边界
```

有多种做法的内容，每种做法都给一个可运行例子和它的输出。

篇幅目标是每章 11000 字符以上，但不为凑字数而写。六件事都交代清楚了仍然不够长，说明这个内容本身只有这么大。

详细规范见 [docs/WRITING-SPEC.md](./docs/WRITING-SPEC.md)。
